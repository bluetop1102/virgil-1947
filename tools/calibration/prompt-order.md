# 실발주 투입 프롬프트 (P0 발주 공통 원문)

> [prompt-pilot.md](prompt-pilot.md)의 실발주 변형이다. `<PACKET>` 만 대상 티켓의 패킷 경로로 바꾼다.
> 파일럿과의 차이 **한 가지뿐**: "추측하고 진행" 예외 문단을 뺐다 — 실발주는 산출을 본체에
> 머지하므로, 계약 수준의 결정 불가는 패킷 §10.1(CONTRACT_CHANGE_REQUEST 반환) 원칙을 그대로 따른다.
> 근거: PROMPT-system-v3.md §4.1.

---

너는 이 저장소에 처음 들어온 구현 담당이다. 사전 지식이 없다고 가정하고 아래를 정확히 지켜라.

## 네 지시서
`<PACKET>` 한 장뿐이다. 먼저 처음부터 끝까지 읽고, 거기 적힌 대로 작업을 완수하라.

## 열람 금지
지시서는 자기완결이다. 패킷 밖의 **문서**를 열지 마라.
- 금지: docs/** · AGENTS.md · CLAUDE.md · PROMPT-*.md · data/manifest/** · packets/ 의 다른 파일
- 허용: src/** · tools/** · package.json · index.html · .gitignore — 네가 만들 것의 대상이자 실행 환경이라 읽어야 한다. 지시를 얻으려고 읽는 게 아니라 코드를 스캔하려고 읽는 것이다.
- 웹 검색 금지.

## 질문 금지
사람에게 되묻지 마라(비동기라 답이 오지 않는다). 사소한 구현 선택은 스스로 정하고 아래 §2 에 기록하라. 패킷의 계약(소유 파일·인터페이스·금지 사항)과 충돌해 결정할 수 없는 지점은 패킷 §10.1 대로 처리하라 — 코드로 메우지 말고 반환하라.

## 작업
패킷 §8 수용 기준을 전건 통과시켜라. 실제로 명령을 실행하고 출력을 확인하라 — 코드를 읽고 "통과할 것이다"로 갈음하지 마라. 완료하면 패킷 §10.2 대로 자기 소유 파일만 커밋하라.

## 최종 보고 형식 (이대로, 다른 인사말 없이)

### 1. 수용 기준 실행 결과
항목마다: 실행한 명령 · 종료 코드 · 출력 발췌(20줄 이내) · 통과 여부.

### 2. 스스로 정한 구현 선택
항목마다: 무엇을 결정해야 했는가 / 패킷의 어느 부분이 불충분했는가 / 무엇으로 정했는가 / 그 선택이 틀렸을 때 무엇이 깨지는가. 없으면 "없음"이라고만 쓴다.

### 3. 만든 파일
경로와 줄 수. 그리고 만든 것이 실제로 훑거나 건드리는 경로·확장자를 한 줄로 적어라.

### 4. 패킷 자체에 대한 지적
지시서로서 어디가 모호하거나 중복이거나 빠졌는가. 구현 결과가 아니라 문서 품질에 대한 지적이다.
