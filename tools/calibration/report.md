> 실행 규약: [protocol.md](protocol.md). 이 리포트가 **"위임 개시 가능" 판정의 근거**다.
> 채워지지 않은 표는 판정 근거가 아니다 — 미실행은 미실행으로 남긴다.

**상태: 파일럿 ① 2에이전트 대조 완료 (Codex · Grok, 동일 패킷).** 파일럿 ② 미착수.

## 0. 선행 시도 기록

### 0.1 무질문 게이트 (내부 서브에이전트) — 미완

캘리브레이션과 같은 측정 장치를 내부 서브에이전트로 먼저 돌렸다. **세션 토큰 한도로 조기
종료**돼 측정값이 없다(패킷 완독·착수까지는 질문 0). 통과로 치지 않는다. §1 이 대체한다.

### 0.2 Codex 1회차 (구 패킷) — 대조군으로 보존

결함 5건을 고치기 **전** 패킷으로 돈 회차다. A1~A3 통과·질문 0·소유 밖 편집 0 이었고,
여기서 나온 지적 6건이 §3 의 수정 원료가 됐다. **현재 대조에는 쓰지 않는다** — 다른
지시서를 받은 회차라 비교 대상이 아니다. 기록은 결함 수정이 무엇을 바꿨는지의 증거로 남긴다.

주요 산출: 추측 4건(검사 범위 · 표출 판별법 · 500줄 줄번호 · 훅 공존 정책) → 그중 3건이
**계약 공백**으로 판정돼 E9 §2 에 판별 규칙 3줄이 신설됐다(Fable `27010a1`).

### 0.3 기계적 자기완결 감사

```
node tools/packet-gen.mjs --audit
```

| 시점 | 잔여 § 좌표 |
|---|---|
| 폐포 도입 전 | 202건 (15장 합계) |
| 폐포 도입 후 | **0건 (16장 전부)** |

## 1. 파일럿 ① 기계형 — `T-P0-01` 계약 린트 커밋 훅

**투입 조건 (양쪽 동일)**: 독립 로컬 클론(HEAD `6776218`) · 소지품 `packets/PACKET-T-P0-01.md`
1장 · 문서 열람 금지 · 질문 대신 추측 기록. 패킷은 계약 반영 후 재생성분(1,307줄).

```bash
codex exec -C $W/cal-codex-P0-01 -s workspace-write --skip-git-repo-check "<프롬프트>"
grok --cwd $W/cal-grok-P0-01 --permission-mode acceptEdits --no-subagents --output-format plain --prompt-file <파일>
```

### 1.1 통과표 (명령 실측)

| 축 | 기준 | Codex | Grok build |
|---|---|---|---|
| 구조 | 소유 파일 2개 정확히 일치 (`tools/lint-contract.mjs`·`tools/install-hooks.mjs`) | **통과** | **통과** |
| 구조 | 규칙 5종 전부 구현 | **통과** | **통과** |
| 구조 | 검사 범위가 계약(E9 §2)과 일치 — `src/**`·`tools/**`·`index.html` 의 `.js`/`.mjs`/`.html`, 500줄은 `.js`/`.mjs` 한정 | **통과** | **통과** |
| 구조 | `lint-allow: display-name` 화이트리스트 구현 | **통과** (2건) | **통과** (5건) |
| 게이트 | A1 `--self-test` — 위반 5종 각 exit 1, 청정 exit 0 | **통과** exit 0 | **통과** exit 0 |
| 게이트 | A2 훅 설치 + 실행 권한 | **통과** exit 0 | **통과** exit 0 (멱등 확인 출력) |
| 게이트 | **A3 차단 경로 왕복** — 위반 스테이지 → exit 1 → reset → exit 0 | **통과** 1→0 | **통과** 1→0 |
| 프로세스 | 질문 0 (되묻기 없음) | **통과** | **통과** |

| 품질 | 출력 포맷 | `[rule] file:line detail` | `rule: file:line: detail` |

**앞의 셋(구조·게이트·프로세스)이 전건 통과다.** 품질 축의 차이(줄수·포맷·화이트리스트 개수)는
규약 §3 대로 기록만 하고 실격으로 치지 않는다.

### 1.2 A3 왕복 실측 (새 수용 기준의 핵심)

```
codex: 위반 스테이지 exit=1 · reset 후 exit=0  → 통과
grok : 위반 스테이지 exit=1 · reset 후 exit=0  → 통과
```

구 A3(깨끗한 인덱스 exit 0 확인)로는 훅이 실제로 막는지 알 수 없었다. 강화된 기준에서
양쪽 다 차단 경로가 재현된다.

### 1.3 계약 수정의 효과 — 측정된 수렴

Codex 1회차의 추측 3건(검사 범위 · 표출 판별법 · 훅 공존)이 계약 공백이었고, E9 §2 에
판별 규칙이 들어간 뒤 **양쪽이 같은 범위를 구현했다** — 계약이 실제로 수렴을 만든 것이
이번 회차의 가장 큰 소득이다.

| 항목 | 계약 명시 후 | 결과 |
|---|---|---|
| 검사 범위 | `src/**`·`tools/**`·`index.html`, 500줄은 `.js`/`.mjs` | 양쪽 일치 |
| 표출 판별 | 리터럴·HTML 텍스트 전수 + `lint-allow` 화이트리스트 | 양쪽 구현 |
| 훅 공존 | 자기 산출이면 멱등 갱신, 아니면 exit 1 | 양쪽 구현 |

### 1.4 Grok 보고 형식 미준수 (프로세스 관찰)

Grok 은 1차 실행에서 작업은 완수했으나 **최종 보고를 지정 형식으로 내지 않았다** —
진행 서술 1줄만 반환했다. 같은 클론에서 보고만 재요청해 §2~§4 를 회수했다(작업 재실행 없음).

이건 패킷 결함이 아니라 **투입 프롬프트/CLI 출력 계약의 문제**다. Codex 는 `-o <파일>` 로
최종 메시지를 따로 받는 경로가 있고, Grok 은 `--output-format plain` 이 진행 로그를 덮어썼다.
protocol.md §4 에 회수 방법을 보강했다.

## 4. 판정

| 조건 | 충족 |
|---|---|
| 1. 기계형 ①에서 **전 에이전트**가 구조·게이트·프로세스 3축 통과 | **충족** — Codex·Grok 양쪽 |
| 2. 창작형 ②에서 구조·프로세스 통과 | 미실행 |
| 3. 리포트 결함 목록 전건 역반영 | **부분** — 1회차 5/5 완료, 2회차 4건 미결(§3.2) |

**판정: 기계형 위임 개시 가능. 창작형은 미검증.**

측정된 것을 그대로 말하면 — **패킷 1장으로 서로 다른 두 외부 에이전트가 질문 0·소유 밖
편집 0 으로 같은 구조를 만들고 게이트 3건을 통과했다.** 검사 범위·표출 판별법·훅 공존이
계약에 명시되자 1회차에서 갈렸던 지점이 양쪽 일치로 수렴했다. 위임 시스템의 핵심 가정
("어떤 에이전트가 봐도 같은 구조가 나온다")이 기계형 티켓에서는 성립한다.

성립하지 않은 것도 분명하다. **창작형은 한 번도 재보지 않았고**, 2회차에서 양쪽이 함께
짚은 계약 공백 4건이 남아 있다. 특히 #6(훅 식별 규약)은 두 산출물이 실제로 다른 마커를
채택한 지점이라 — 지금 둘을 같은 트리에 넣으면 서로의 훅을 남의 것으로 오인한다.

**다음 순서**: (1) §3.2 의 계약 공백 4건을 HANDOFF 로 닫는다 → (2) ①의 산출 중 하나를
본체 P0 에 반영(채택 기준: 계약 준수 동률이므로 구현이 단순한 쪽 우선) → (3) 그 위에서
② 창작형 착수. P0 발주 자체는 지금 열어도 된다 — 기계형 조건이 충족됐다.
