# 교차 에이전트 캘리브레이션 — 실행 규약

> 무엇을 재는가: **패킷 1장이 에이전트를 바꿔도 같은 구조를 내는가.**
> 재지 않는 것: 어느 모델이 더 똑똑한가. 편차는 기록만 하고 실격 사유로 쓰지 않는다.
> 산출: [report.md](report.md) — 이 리포트가 "위임 개시 가능" 판정의 근거다.

## 0. 실행 전 확인 (비용 게이트)

외부 에이전트 실행은 **토큰이 실비**다. 착수 전 사용자 승인을 받는다. 승인 없이 돌리지 않는다.

## 1. 파일럿 2건 — 왜 이 둘인가

| 파일럿 | 티켓 | 성격 | 이걸로 무엇을 아는가 |
|---|---|---|---|
| ① 기계형 | `T-P0-01` 계약 린트 커밋 훅 | **정답 수렴형** — 통과/실패가 명확 | 패킷이 기계 과제를 결박하는가. 여기서 갈리면 패킷 결함이 확실하다 |
| ② 창작형 | `T-P1-02` 다이치 리그 | **정답 발산형** — 실루엣의 답은 여럿 | 계약이 창작 폭을 남기면서도 구조를 고정하는가 |

기계형이 갈리면 발산 때문이 아니라 지시 결함이다. 창작형이 갈리는 것은 정상이고,
**구조가 갈리는 것만** 결함이다. 이 둘의 대조가 "편차"와 "결함"을 분리하는 장치다.

## 2. 투입 조건 (전 에이전트 동일)

- **소지품은 패킷 1장뿐이다.** `packets/PACKET-<id>.md` 를 그대로 준다.
- **열람 금지**: `docs/**` · `AGENTS.md` · `CLAUDE.md` · `PROMPT-*.md` · `data/manifest/**` ·
  다른 패킷. **허용**: `src/**` · `tools/**` · `package.json` — 검사·구현 대상이지 지시서가 아니다.
- **각 에이전트는 독립 클론에서** 돈다. 서로의 산출을 보지 못한다.
  ```bash
  git clone --local <저장소> ../Worktrees/cal-<agent>-<ticket>
  ```
  **워크트리를 쓰면 안 된다** — 워크트리는 `.git/hooks` 를 본체와 공유하므로, 패킷대로
  커밋 훅을 설치하는 순간 본체 저장소의 커밋까지 그 훅에 걸린다(T-P0-01 이 정확히 그 티켓이다).
  로컬 클론은 오브젝트를 하드링크해서 2GB 저장소도 0.2초에 끝나고 훅은 완전히 분리된다.
- **질문 금지 · 추측 기록 의무**: 되묻지 말고, 패킷만으로 결정할 수 없어 추측한 지점을
  전부 기록하게 한다. 이 기록이 곧 패킷 결함 후보 목록이다.
- 반환 형식은 패킷 §10 그대로. **단 한 가지만 다르다**: 패킷 §10.1 은 "결정할 수 없으면
  추측하지 말고 반환하라"인데, 이 실험에서는 **추측해서 진행하고 그 추측을 기록**하게 한다.
  기록이 곧 반환이다 — 반환하고 멈추면 게이트 통과 여부를 측정할 수 없기 때문이다.
  이 예외를 프롬프트에 명시하지 않으면 에이전트가 두 지시의 충돌을 지적한다(Codex 실측).

## 3. 동일성의 정의 — 픽셀 동일이 아니다

| 축 | 기준 | 판정 방법 |
|---|---|---|
| **구조** | 소유 파일 경로·export 이름·이벤트 어휘가 매니페스트와 일치 | `data/manifest/<id>.json` 과 대조 |
| **게이트** | 패킷 §8 수용 기준 전건 통과 | 명령 실제 실행 · 출력 첨부 |
| **프로세스** | 질문 0 · 소유 밖 파일 편집 0 | 추측 기록 개수 · `git diff --name-only` |
| **품질** | 샷·산출물을 같은 루브릭으로 채점 | **편차는 기록만. 실격 아님** — 수렴은 판정 라운드의 일이다 |

앞의 셋이 갈리면 **패킷 결함**이다. 넷째만 갈리면 정상이다.

## 4. 실행

```bash
# 0) 승인 확인 후
node tools/packet-gen.mjs T-P0-01 T-P1-02        # 패킷 최신화
node tools/packet-gen.mjs --audit                # 잔여 좌표 0 확인 — 0이 아니면 먼저 닫는다

# 1) 에이전트별 독립 클론 (워크트리 아님 — §2 참조)
W=../../Worktrees
git clone --local . $W/cal-codex-P0-01
git clone --local . $W/cal-grok-P0-01
# … T-P1-02 도 동일하게

# 2) 패킷 1장으로 투입 (§2 조건). 헤드리스 호출:
codex exec -C $W/cal-codex-P0-01 -s workspace-write -o codex.out "$(cat 프롬프트)"
grok --cwd $W/cal-grok-P0-01 --permission-mode acceptEdits --output-format plain --prompt-file 프롬프트

# 3) 회수 — 각 클론에서
git -C $W/cal-<agent>-<ticket> status --short    # 소유 축(패킷 §2 목록 밖 파일이 있으면 이탈)
git -C $W/cal-<agent>-<ticket> log --oneline -3
# 게이트 축은 패킷 §8 의 명령 그대로, 해당 클론 안에서
```

## 5. 리포트 작성 규칙

- **통과표는 명령 출력으로 채운다.** "통과함"이라고 쓰지 않고 종료 코드와 출력 발췌를 붙인다.
- **패킷 결함 역반영 목록이 이 리포트의 본체다.** 추측 기록·이탈이 나온 지점마다:
  어느 절이 불충분했는가 → 매니페스트/생성기 중 어디를 고치는가 → 고친 뒤 재생성했는가.
- 결함을 고친 뒤에는 **패킷을 다시 찍고**(`packet-gen`) 잔여 좌표 0 을 재확인한다.
  지시서를 손으로 고치지 않는다 — 매니페스트나 생성기를 고치고 찍는다.

## 6. 판정 — "위임 개시 가능"의 조건

1. 기계형(①)에서 **전 에이전트가 구조·게이트·프로세스 3축 통과**.
2. 창작형(②)에서 **구조·프로세스 통과**(품질 편차는 허용).
3. 리포트의 패킷 결함 목록이 **전건 역반영 완료**.

셋을 못 채우면 외부 발주를 열지 않는다. 계약이 실코드와 어긋난 상태의 외부 투입 금지
원칙(E10 §3)과 같은 취지다 — 여기서 새는 것은 나중에 통합 비용으로 돌아온다.
