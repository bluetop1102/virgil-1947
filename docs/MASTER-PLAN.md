## 2. 괴담 레이어 — "공포 호텔"의 공포 층위

**원칙: 괴담은 대기·환경서사·발화로만 존재한다. 증거 그래프(§4)에 초자연 노드는 들어가지 않고,
사건은 물질 인과로 닫힌다.** 괴담의 서사 기능은 장식이 아니라 셋이다.

- **은폐막** — 도일이 괴담 뒤에 숨는다. "9층 물소리요? 옛날부터 그랬습니다." 괴담이 이상 신호를
  선제적으로 무해화해 온 것이 이 호텔에서 살인이 가능했던 구조적 이유가 된다.
- **미제 엔딩의 의미화** — 지목 실패 시 사건은 괴담이 되어 호텔에 흡수된다(엔딩 자막). 실패가
  패배 화면이 아니라 이 호텔의 작동 방식을 보여주는 정식 결말이 된다(기존 "미제는 정식 엔딩" 원칙 강화).
- **공포 밀도** — 조용한 공포의 재료 공급. 점프스케어 금지·초자연 실재 금지는 유지.

**괴담 유닛 스키마** (STORY v2에 3~5개 집필): `{소문 텍스트, 전달 매체, 물질적 진상(사건 접점 유무)}`.
시드: ① "9층에서 물소리가 나면 비가 온다" (진상: 노후 배관 — 넬 사건의 소리를 삼킨 소문)
② 채광정 괴담 — "9층에서 떨어진 여자가 아직 내려가는 중이다" (진상: 넬 사건의 왜곡 전승)
③ 개업 연도(1912, v2 확정)부터의 내력 한 줄 — 지진·금주법 시대 지하 등 시대 질감용.
**전달 매체**: 로비 라디오, 944호 신문 스크랩, 숙박부 여백 낙서, 린넨실 벽 낙서, 루이즈 발화.
인물은 4인 고정이므로 괴담 전달자는 환경 + 4인의 태도 차이(§3)로만.

## 4. 사실 그래프 — 개연성의 기계 게이트

**목적: 내러티브 축에도 그래픽 축의 `pix diff`에 상당하는 회귀·모순 검출기를 만든다.**
그리고 명제 단위 데이터 구조 자체가 2단 커널 스왑(§5.4)의 전제 조건이다.

- **노드**: `FACT`(명제 문장 — 표 A·B의 셀), `EVIDENCE`(14종), `STATEMENT`(진술 — 진실/거짓),
  `LORE`(괴담 유닛 — **검증 제외 마커**, 사건 인과에 참여 금지).
- **엣지**: `supports`(증거→명제), `refutes`(증거→거짓 진술), `hides`(거짓 진술→가리는 명제),
  `unlocks`(진술 결과→증거/플래그).
- **구현**: `script.js` v2가 이 스키마로 데이터화(현행 claim이 이미 명제 문장이라 이행 비용 낮음).
  `tools/factcheck.mjs` 신설.

**검증 4종 (커밋 게이트 — 콘솔 0과 동급)**

| # | 검증 | 통과 조건 |
|---|---|---|
| F1 | 반박 커버리지 | 모든 거짓 STATEMENT에 도달 가능한 refutes 경로 존재 |
| F2 | 타임라인 일관성 | 동일 시각 동일 인물의 위치 모순 0 · 증거 원산지 셀 결박 100% |
| F3 | 도달성 | 3링크 각각 수집 가능 경로 성립 + 최악 소각 경로에서도 미제 엔딩 도달(진행 불능 0) |
| F4 | 고아 노드 | 어떤 엣지에도 연결되지 않은 FACT/EVIDENCE 0 (죽은 콘텐츠 금지) |

## 5. 게임플레이·이벤트 설계

### 5.1 코어 루프 (확정)

탐색(증거 수집·환경서사·괴담 접촉) → 심문(진술별 3선택 + 텔 관찰) → 수사노트 정리 →
지목(3링크 증거판) → 엔딩 3종(완전/부분/미제). 플레이 40~60분, 3막, 막 경계 체크포인트 저장(§8).

### 5.2 이벤트 시스템

트리거 4종: **진입**(공간) · **획득**(증거) · **플래그**(two-voices 등) · **페이즈**(막 내 시간 단계).
기존 bus 계약 위에 표준 이벤트 추가분만 얹는다 (`ARCHITECTURE.md` §5 개정안):

| 이벤트 | payload | 용도 |
|---|---|---|
| `act:phase` | `{act, phase}` | 막 내 페이즈 전환(조명·오디오 무드 연동) |
| `lore:heard` | `{id, medium}` | 괴담 유닛 접촉(노트 괴담 면에 축적) |
| `npc:sighted` | `{npc, kind}` | 프리젠스 목격(도일 실루엣 등 — 정보 없는 존재감) |
| `checkpoint:saved` | `{act}` | 막 경계 저장 |

### 5.3 막별 이벤트 표 (레벨 발주의 수용 기준)

### 5.4 심문·지목 — 현행 규칙 승계 + 2단 커널 계약

심문 판정표·소각·재심문·카메라 문법(N5)·힌트 금지 전부 현행 유지. **지목의 2단 설계**:

- **1단(수직 슬라이스~게이트 4)**: 현행 3링크 증거 조합 지목. 전 스크립트, 런타임 AI 없음.
- **2단(Phase 4)**: 자유 서술 입력 → 사실 그래프의 FACT 명제와 의미 매칭(AI 판정) → 기존 판정
  결과·연출 재사용. **스왑 경계**: 변경은 `deduction.js`·`interrogation.js`의 입력층에 한정,
  판정 결과 처리·연출·데이터는 불변. 판정 배터리(정답/오답/무관 각 N건) QA가 게이트.
  API 키는 2단에서만 필요 — 1단 산출물은 무키 실행 유지(배포·심사 안전).

### 5.5 텔 — 완전판별기 함정의 기계 감시

원칙 유지: 불안 텔과 거짓 텔이 겹치게. 8/4 롤백에서 "움직이면 100% 거짓"인 완전판별기가 실제로
나왔으므로 P5 게이트(§6)로 기계 감시한다 — 스크립트 전수에서 거짓 진술과 텔 발화의 상관이 1.0이면
FAIL(불안 시 텔 발화가 전체 텔 발화의 30% 이상이어야 PASS).
