# 신선 에이전트 무질문 구현 테스트 — 프로토콜 (M1 측정 + 전제 검증 겸용)

> 요소 1개당 신선 에이전트 1기. 에이전트는 제작 맥락(세션 히스토리·ROUNDS-PLAN·planning.md·
> git log)을 받지 않는다. 아래 프롬프트를 그대로 주고, 출력 JSON을 디렉터가 판정한다.

## 신선 에이전트 프롬프트 (템플릿 — `{E##}` 치환)

너는 이 프로젝트를 처음 보는 구현 담당이다. 다음 파일만 읽는다:

1. `docs/design/{E##}.md` — 네가 구현 계획을 쓸 요소
2. `docs/design/E0-index.md` — 진실원 지도 (링크 해석용)
3. 요소 문서가 링크로 가리키는 진실원 파일 (`docs/STORY.md` · `docs/design/case-graph.json` ·
   `docs/ARCHITECTURE.md` · `docs/AAA-RUBRIC.md` 중 링크된 것)

과업: 이 요소의 **구현 계획**을 티켓 수준으로 작성하라 — 만들 파일, 작업 순서, 각 단계의
수용 기준. 계획을 쓰다가 답이 없어 진행이 불가능한 지점이 나오면 멈추지 말고 다음 규칙으로 기록한다:

- **BLOCKING**: 이 답 없이는 해당 계획 절을 쓸 수 없다. 가정으로 대체하면 구현이 갈라진다.
- **ASSUMPTION**: 합리적 기본값을 가정하고 진행 가능하다. 가정 내용을 명시한다.

주의: 질문하기 전에 제공된 파일에서 답을 실제로 찾아라. 문서에 있는 답을 질문으로 올리면
그 질문은 무효 처리된다.

출력 (이 JSON만):

```json
{
  "element": "E##",
  "plan": ["티켓 1: … (수용 기준: …)", "티켓 2: …"],
  "blocking": [
    {
      "question": "질문 원문",
      "cause": "MISSING | AMBIGUOUS | CONFLICT",
      "where": "어느 파일 어느 절을 읽다가 막혔나",
      "whyBlocking": "가정으로 대체하면 무엇이 갈라지나"
    }
  ],
  "assumptions": [ { "topic": "…", "assumed": "…" } ]
}
```

`cause` 정의 — MISSING: 정보 자체가 어느 파일에도 없다 · AMBIGUOUS: 서술은 있으나 두 가지 이상으로
읽힌다 · CONFLICT: 문서 간 서술이 모순된다.

## 디렉터 판정 규칙

1. `blocking` 각각에 대해 답이 제공 문서에 **명시 좌표로 존재**하는지 확인한다.
   - 존재하면 **discount** — 질문 수에서 제외하되, 에이전트가 왜 못 찾았는지(링크 부재·
     제목 아래 묻힘)를 ROUNDS-PLAN에 기록한다. 같은 discount가 2회 재발하면 발견성 결함으로
     BLOCKING 승격.
   - 존재하지 않으면 유효 차단성 질문으로 계수한다.
2. 요소 점수: 유효 차단성 질문 0건=10 · 1건=6 · 2건+=4.
3. `cause` 분포가 Phase C 전제 검증의 실측이다 — MISSING 우세면 정보 추가, AMBIGUOUS 우세면
   서술 재작성, CONFLICT면 진실원 단일성 위반 수색. 수정 방향은 이 분포를 따른다.
