# 발사문 — 체험 리뷰 (Fable 단독 세션)

> 실행자: **Fable 새 세션**. 이 세션의 일은 **판정**이다 — 구현·발주·머지는 하지 않는다.
> 선행: P1 12장 전건 머지 완료(2026-08-08). 게임이 1막을 완주한다. v4 발사문은 §4에서
> "감각 판정은 하지 마라"로 끝났고, 그 자리가 이 문서다.
> 마감: 리허설 **8/8** · 제출 **8/10**.

## 0. 왜 너를 부르는가

지금까지의 모든 게이트는 **기계 판정**이다 — 배터리·factcheck·린트·샷 게이트·완주 봇.
전부 통과한다. 그런데 이 프로젝트는 그 상태에서 **핵심 배선이 세 번 비어 있었고**
(`evidence:granted` 소비자 0 · QA 관찰형 진입점 0 · `interrogation:start` 발화자 0)
기계 게이트는 세 번 다 통과시켰다. 기계가 못 보는 축이 남아 있다는 뜻이다.

너는 **게슈탈트**를 본다. 항목별 점수가 아니라 "이게 상용 게임으로 보이는가", "무섭고
수사하는 맛이 나는가", "1947년 호텔에 있는가"를 본다. 감각 판정은 이 세션의 배타 권한이다.

## 1. 체험 대상

**배포 링크 — 심사자가 볼 것과 동일한 산출물이다.**

```
https://bluetop1102.github.io/virgil-1947/
```

조작: 클릭으로 마우스 잠금 · **WASD** 이동 · **E** 상호작용 · **Tab** 수사노트 · **Esc** 설정.

로컬로 봐야 하면 `npm run dev` 후 `http://127.0.0.1:5173/`.
공간 단독 확인은 `?scene=` — `lobby-night` · `corridor-night` · `room-dusk` · `bathroom` ·
`rooftop-rain` · `interrogation`. 정지 화면만 필요하면 `npm run shot` 산출(`shots/`)을 봐도 되지만,
**체험 판정은 반드시 직접 걸어본 뒤에 한다** — 이 세션의 존재 이유가 정지 샷으로 안 잡히는 축이다.

## 2. 판정 기준

`docs/AAA-RUBRIC.md` 가 정본이다. 세 게이트로 판정한다.

| 게이트 | 조건 |
|---|---|
| 1 그래픽 | 전 항목 8+ · **실격 0** |
| 2 내러티브 | 전 항목 8+ |
| 3 블라인드 | 상용 게임으로 오인 또는 즉답 불가 |

**인물 판정의 전제(디렉터 확정, 2026-08-07)**: 절차 휴머노이드는 포토리얼 인체가 아니라
**의도된 퍼펫/마리오네트**(1947년 복화술 인형 계열)다. 포토리얼과 대조하지 마라 —
완성도 기준은 관절·재질 일관성 · 마모 밀도 · 환경 정합 4축이다(AAA-RUBRIC v3.1 D4 인물 예외,
E4 §3 아트 디렉션 선언). **의도된 인형 관절은 실격이 아니다.**

## 3. 이미 아는 잔여 3건 — 다시 찾지 마라

시간 낭비를 막기 위해 먼저 준다. 셋 다 등재돼 있고 제출 차단은 아니다.

1. **`--paced` 실시간 모드가 막 전환에 도달하지 못한다.** 증거 4종 획득까지는 성립하고
   `--fast` 완주는 통과한다. 완주 봇 자체의 잔여다(HANDOFF 등재).
2. **전 샷 스위트에서 atmo 프로브에 검은 폴리곤 아티팩트.** 단독 촬영은 깨끗하다.
   기전 확정 — `engine.js:127` 의 `advanceTo` 가 `Math.max(t, self.time)` 라 샷 선언 시간이
   무시되고 t≈55에 찍힌다. **머지 이전 커밋에서도 재현되는 기존 결함**이다.
3. **레벨 3종(코리도·942호·옥상)은 P2 범위라 아직 없다.** 그래서 해당 샷 6개는 빈 좌표를
   찍는다 — `npm run shot` 28/28 중 **실질 판정은 22개**다. 지금 걸을 수 있는 정식 공간은
   **로비 하나**이고, 심문·수사노트·지목판은 성립한다.

`docs/RESUME.md` 의 **기각된 가설 9건**도 읽어라. 여기 적힌 것을 다시 파는 것이
이 프로젝트에서 가장 크게 낭비된 지점이다.

## 4. 산출물

`docs/design/` 과 `STORY*`·`ARCHITECTURE.md`·`AAA-RUBRIC.md` 는 **편집 금지**다.
판정 결과는 두 곳에 쓴다.

1. **`docs/reviews/fable-experience-<날짜>.md` 신설** — 게이트 1·2·3 각각의 판정,
   항목별 점수와 **그 점수를 8+로 올리려면 무엇이 달라져야 하는지**를 구체로 적는다.
   "분위기가 부족하다" 같은 문장은 쓰지 마라 — 어느 화면의 무엇이, 어떻게 보여야 하는지를
   쓴다. 스크린샷 경로를 붙인다.
2. **`docs/HANDOFF.md` 하단** — 소유자에게 넘길 항목만. 기존 항목 형식을 모방한다.
   각 항목에 **루브릭 축**과 **실격 여부**를 명시한다.

## 5. 하지 말 것

- **코드 수정·발주·머지 금지.** 이 세션은 판정만 한다. 고쳐야 할 것은 HANDOFF로 넘긴다.
- **기계 게이트 재실행으로 시간을 쓰지 마라.** 이미 전건 통과 상태이고 실측은
  `tools/calibration/report.md` §5.10에 있다. 네가 볼 것은 그 게이트가 못 본 축이다.
- **이력 재작성 금지**(제출 요건) · 외부 에셋 다운로드 금지 · `Math.random`/`Date.now` 직호출 금지.
- 실제 사건 피해자를 재현하지 않는다. 인물·사건은 전부 허구다.

## 6. 완료

게이트 1·2·3 판정과 §4 산출물 두 건. **점수만 매기고 끝내지 마라** — 8+ 미달 항목마다
"무엇이 달라져야 8인가"가 없으면 다음 라운드가 그걸 못 고친다.

판정이 끝나면 사용자에게 **제출 가능 여부와 남은 시간에 무엇을 먼저 고칠지**를 한 문단으로
보고한다. 마감이 8/10이고 리허설이 8/8이라, 전부 고치는 것이 아니라 **무엇을 포기할지**를
정하는 것이 이 판정의 실질이다.
