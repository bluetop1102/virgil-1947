## 0. 요약 — 세 문장

1. **이 게임은 AI로 만든 것이 아니라 AI를 통제하는 시스템으로 만들었다.** 사람이 쓴 것은
   목표·루브릭·게이트이고, 코드·문서·검증기는 에이전트가 썼다. 지시서조차 손으로 쓰지 않고
   데이터에서 찍어낸다(§2.3 — 매니페스트 18장 → 패킷 18장 29,435줄, 생성기 `tools/packet-gen.mjs`).
2. **에이전트를 믿지 않고 기계로 판정했다.** 검증 도구가 **에이전트의 완료 보고를 세 번
   뒤집었고**(설계된 음악이 실제로는 한 번도 울리지 않았고, 심문이 게임에서 가장 조용한
   구간이었으며, 고쳤다고 보고된 노출 상한은 애초에 구현돼 있지 않았다), 그와 별개로 **검증
   도구 자신의 오판을 한 번 잡았다**(§3.2). 전부 사람의 인상이 아니라 로그가 판정했다.
3. **AI가 만든 것과 사람이 조달한 것을 전부 공개했다.** 게임 월드의 텍스처·지오메트리·조명·
   효과음은 외부에서 받은 것이 하나도 없는 절차 생성이고, **AI 생성 에셋은 타이틀 화면 배경
   1장뿐이며 그 프롬프트 전문이 저장소에 있다.** 외부 다운로드는 CC BY 4.0 음원 3곡이 전부다(§6).
   런타임에는 AI가 없다 — 출하 빌드는 API 키·계정·네트워크를 요구하지 않는다.

### 0.1 이 문서에서 쓰는 말 여섯

| 말 | 뜻 |
|---|---|
| **발사문(發射文)** | 에이전트 세션 하나를 시작시키는 지시서. 두 종류다 — 사람이 쓴 `PROMPT-*.md` 29장, 기계가 찍어낸 **패킷** 18장 |
| **매니페스트** | 작업 티켓 1장을 JSON 필드로 적은 것. 소유 파일·의존·수용 기준이 필드로 고정된다 |
| **패킷** | 매니페스트에서 **자동 생성한** 발사문. 참조 문서의 원문이 통째로 인라인돼 있어 그것만 읽으면 된다 |
| **게이트** | 통과/실패가 기계로 갈리는 검사. 통과한 것만 다음 단계로 넘어간다 |
| **하네스 · 프로브** | 게임을 자동으로 실행시켜 재는 장치(하네스)와, 그 안에서 한 가지 항목을 재는 개별 검사기(프로브) |
| **소각** | 이 게임의 규칙. 심문에서 틀린 증거를 내밀면 그 진술의 정보가 회차 안에서 영구 소멸한다 |

`P0`·`P1`은 제작 단계다 — P0는 새 기능 없이 청소·게이트만 하는 정지작업, P1은 게임 전체를
얇게 훑는 대신 **1막 하나를 끝까지 되게 만드는** 수직 슬라이스. `E0~E10`은 설계 문서 번호,
`J1~J6`은 자체 채점 루브릭의 축 번호다.

## 1. 무엇을 AI로 했는가 — 한 장 요약

| 층 | 사람이 한 것 | AI가 한 것 | 증거 |
|---|---|---|---|
| 기획 | 장르·톤 결정, 요소 분해 지시 | 설계 문서 E0~E10 11편 + 사건 그래프·스키마 (`docs/design/` 17파일 3,546줄) | `docs/design/**` |
| 계약 | 소유권·이벤트 어휘 규칙 제정 | 계약 문서화·린터 구현 | `docs/ARCHITECTURE.md` · `tools/lint-contract.mjs` |
| 위임 | 티켓 보드 승인 | 매니페스트 전사 · **패킷 18장 자동 생성** | `data/manifest/*.json` · `packets/*.md` |
| 구현 | 발주·회수·머지 판정 | 게임 코드 86파일 23,488줄 | `src/**` · 커밋 198개 |
| 검증 | 루브릭 설계·통과 기준 확정 | 검증 도구 25파일 5,312줄 · 블라인드 채점 | `tools/**` · `docs/reviews/**` |

사람의 개입은 **결정**에 몰려 있고, AI의 개입은 **산출**에 몰려 있다. 다만 이 선을 깨끗한
이분법으로 주장하지는 않는다 — §3.2의 원인 진단(음악이 안 울린 이유가 오디오 컨텍스트 생성
타이밍 경합이라는 특정)은 **판정 세션이 한 것**이고, 사람이 한 것은 그 진단을 받아 무엇을 언제
발주할지 정한 것이다. 진단도 AI가 하고 사람은 판을 정한다 — 이 배치를 유지하기 위해 만든 것이
아래 §2의 4층 구조다.

## 2. 구조 — AI 파이프라인 4층

```
[0] 계약층   ARCHITECTURE.md — 파일 소유권 · 이벤트 어휘 · 재질/조명 팩토리 · 결정론
                  ↓  위반은 커밋 훅이 차단한다
[1] 사양층   E0~E10 설계 문서 + case-graph.json — 한 사실은 한 파일에만 산다
                  ↓  기계 전사
[2] 위임층   data/manifest/*.json (18장) → tools/packet-gen.mjs → packets/PACKET-*.md
                  ↓  자기완결 발사문 1장 = 에이전트 1명의 소지품 전부
[3] 판정층   기계 게이트 — factcheck · 계약 린트 · 완주 봇 · 샷 하네스 · 배포 검증 · JUDGE 프로브
                  ↓  통과한 것만 판이 갱신된다
```

**핵심은 [2]다.** 프로즈로 쓴 티켓 표는 "이 파일도 만져도 되나", "이건 어느 범위까지인가"가
읽는 에이전트마다 갈린다. 매니페스트는 그 항목들을 **필드로 고정**한다 — 소유 파일 목록, 선행
의존, 수용 기준, 배정 모델이 각각 하나의 필드이고, 검사기가 8규칙으로 그 필드들을 잠근다
(§2.3). 해석의 여지가 없어지는 것이 아니라 **해석의 여지가 필드 밖으로 밀려나고, 필드는
기계가 검사한다.** (같은 지시로 여러 에이전트를 돌려 산출이 일치하는지 보는 대조 실험은 하지
않았다. 여기서 주장하는 것은 산출의 동일성이 아니라 **작업 경계의 동일성**이다.)

### 2.1 계약층 — 에이전트가 서로를 망가뜨리지 못하게

병렬 에이전트 4개가 같은 픽셀을 동시에 만져 **무엇이 무엇을 망쳤는지 귀속이 불가능해진 사고**를
겪었다(`docs/RESUME.md` §5 — 3라운드 연속 평균 4.6, 매 라운드 무언가 좋아지고 무언가 나빠지는
진동). 대응은 두 가지였다. 라운드당 담당 1명으로 직렬화했고, **파일 단위 배타 소유**로 전환했다.
남의 파일을 고쳐야 하면 고치지 않고 `docs/HANDOFF.md` 큐에 요청을 남긴다(현재 3,398줄, 교차
요청과 그 처리 기록이 전부 남아 있다).

계약 위반 5종은 커밋 훅이 기계로 차단한다 — 재질 팩토리 밖 재질 생성 · 대기 모듈 밖 광원 생성 ·
`Math.random()`/`Date.now()` 직호출 · 파일 500줄 초과 · 구 작품명 표출 문자열.

```bash
$ node tools/lint-contract.mjs --self-test
SELF-TEST PASS × 11 · FAIL 0        # 규칙이 실제로 잡는지 + 우회가 막히는지 (2026-08-10 실행)
```

린터는 **스테이지 범위**로 돈다(`.git/hooks/pre-commit` → `lint-contract.mjs --staged`). 그래서
새 위반은 커밋 자체가 막히고, 훅 도입 이전의 잔여 위반은 남는다 — 현재 4건이다. 3건은 셰이더
캐시 키 문자열(`'cecil' + key` 형태)이고 1건은 팩토리 밖 `MeshBasicMaterial` 생성이다. 앞의
3건은 **화면에 표출되지 않는 내부 식별자**라 표출명 요건과 무관하다. 숨기지 않고 여기 적는다.

### 2.2 사양층 — 형용사를 데이터로 내림

사건은 문서가 아니라 그래프다. `docs/design/case-graph.json` — 시점 16 · 인물 7 · 장소 12 ·
사실 27 · 증거 14 · 진술 14 · 지목 링크 3 · 괴담 4 · 엔딩 3. 거짓 진술에는 `refutedBy`(반박 증거)가
필수이고, 괴담 노드는 사건 인과에 참여할 수 없다.

이 규칙을 `tools/factcheck.mjs`가 감시한다. "진행 불능이 발생하지 않는다"가 신념이 아니라
통과/실패다:

```bash
$ node tools/factcheck.mjs        # 2026-08-10 실행 — 13게이트 전건 PASS (아래는 그중 3줄 발췌)
PASS F3  3링크 최선 경로 성립 · 최악 소각 경로: 링크 1개 → 미제 엔딩 도달 (진행 불능 0)
PASS J3  시도 공간 = 증거쌍 × 명제 풀(9) — 최선 91쌍 → 819 · 최악 소각 55쌍 → 495 (하한 300)
PASS P5  불안 텔 진실 진술 4 / 텔 발화 진술 11 = 36% · 거짓·텔 상관 0.522
```

세 번째 줄이 이 게임의 설계 주장을 기계로 잠근 자리다 — **텔(거짓말의 몸짓)이 거짓과 상관이
있되 결정적이지 않아야 한다.** 상관 1.0이면 텔이 정답 표시등이 되고, 0이면 관찰이 무의미해진다.
0.522라는 값과 "불안 텔이 진실 진술에도 36% 실린다"는 조건을 게이트가 지킨다.

### 2.3 위임층 — 지시서를 찍어낸다 (이 프로젝트 고유)

| 산출물 | 파일 | 역할 |
|---|---|---|
| 스키마 | `docs/design/manifest.schema.json` | 티켓 1장의 필수 필드 정의 |
| 매니페스트 | `data/manifest/T-P{0,1}-*.json` 18장 (P0 6 + P1 12) | 티켓 보드의 기계 전사본 |
| 검증기 | `tools/manifest-check.mjs` | 8규칙 — 소유 배타성·§좌표 실재·이벤트 어휘·순환 0·명령 실행 가능성 |
| 생성기 | `tools/packet-gen.mjs` | 티켓 → 자기완결 발사문 |
| 패킷 | `packets/PACKET-*.md` 18장 · 29,435줄 | 에이전트 1명이 받는 소지품 전부 |

**자기완결의 정의**: 패킷은 자기가 참조하는 계약 절의 **원문을 인라인**하고, 사건 그래프 노드를
JSON 그대로 박고, 이벤트 표의 해당 행과 카메라 정의를 뽑아 넣는다. 받은 에이전트는 패킷 밖
문서를 열지 않는 것이 규약이고, 그 규약이 성립하려면 패킷이 완결이어야 한다.
**질문이 나오면 에이전트가 아니라 패킷을 고친다.**

```bash
$ node tools/manifest-check.mjs                 # 2026-08-10 실행
위상 정렬 (순환 0): T-P0-01 → T-P0-03 → … → T-P1-11 → T-P1-12
발견 0 — 매니페스트가 계약과 정합한다.
```

**검증기가 실제로 잡은 것**(작문이 아닌 실측):

- 변이 12종 주입 시 12/12 검출 — 허용값 밖 모델 배정 · 순환 의존 · 없는 절 지목 · 어휘 밖
  이벤트 이름 · 존재하지 않는 도구를 부르는 수용 기준 등(`PROMPT-system-v2.md` §A 기록).
- 정본 대상 실행에서 **티켓 보드의 실결함 1건 검출** — 두 티켓이 같은 파일을 소유하면서 "상호
  독립"으로 선언돼 있었다. 동시 발주하면 한쪽 산출물이 조용히 사라지는 구조다.
- 배포 검증기 `tools/serve-check.mjs`가 **서브패스 배포에서 에셋 404 5건과 부팅 실패**를 잡았다.
  vite 개발 서버는 경로를 보정해 주므로 이 결함은 개발 중에 보이지 않고 **배포에서만 드러난다**.
  GitHub Pages 프로젝트 사이트가 서브패스라 이 조합이 그대로 심사 경로였다.

| 빌드 | 루트 배포 | 서브패스 배포 |
|---|---|---|
| `npm run build` (base=`/`) | PASS | **FAIL — 에셋 404 5건, 부팅 실패** |
| `npm run build:pages` (base=`./`) | PASS | **PASS** |

### 2.4 실행층 — 병렬 세션과 커밋 규약

구현은 여러 에이전트 세션이 **같은 워킹트리에서 동시에** 돈다. 이때 깨지는 것은 코드가 아니라
git 인덱스다 — `git add -A`나 `git commit -a`를 두 세션이 쓰면 한 커밋에 두 세션의 작업이
섞이고, 라운드↔변경 대응이 무너진다. 그래서 규약은 하나다: **자기 소유 경로를 pathspec으로
명시해서만 스테이지한다**(`AGENTS.md` 병렬 세션 커밋 규약).

이 규약이 실제로 작동했다는 것도 감사로 확인했다. 병렬 4세션 회수 시점 감사 기록:

> **커밋 12건 전수 감사: 섞임 0.** 각 커밋이 단일 축이고 소유 밖 파일 0건.
> — `docs/HANDOFF.md` "S0 회수" 블록(2026-08-08)

마지막 라운드(JUDGE 라운드, 2026-08-10)에서는 4세션 16커밋이 같은 방식으로 회수됐고, 규약
이탈 2건(문서 파일을 커밋에 포함)이 발견돼 **실해 없음으로 판정하고 기록에 남긴 뒤 규칙을
개정**했다(문서는 append만, 게이트가 일괄 커밋). 이탈을 지우지 않고 남기는 것이 이 공정의
산출물 중 하나다.

### 2.5 판정층 — 구현자와 판정자를 분리

**구현한 에이전트가 자기 산출을 채점하지 않는다.** 채점은 구현 컨텍스트가 없는 별도 세션이
하고, 판정 근거는 인상이 아니라 프레임·로그·상태 직렬화여야 한다(`docs/JUDGE-RUBRIC.md` §1).

| 축 | 판정 수단 | 상태 |
|---|---|---|
| 사실 그래프 | `tools/factcheck.mjs` — 13게이트 | 가동 · 전건 PASS |
| 계약 위반 | `tools/lint-contract.mjs` + pre-commit 훅 | 가동 · 자기검사 11/11 · **훅 도입 이전 잔여 위반 4건**(§2.1) |

## 3. 검증 하네스 — 기계가 판정을 뒤집은 기록

이 프로젝트에서 가장 비싼 교훈은 **"에이전트의 완료 보고는 증거가 아니다"** 였다. 아래는
보고와 실측이 갈린 사례이고, 전부 하네스가 잡았다.

### 3.1 프로브 4종 — 무엇을 재는가

`tools/judge-probes/`는 헤드리스 Chromium(ANGLE Metal 실가속, 1600×900)으로 **배포본을 직접
찔러** 사람의 동선을 걷는다. 이동·상호작용·선택은 실제 키 입력이다.

- `probe-audio.mjs` — 마스터 버스에 Analyser를 붙여 **250ms 간격 RMS(dBFS) 타임라인**을 뜬다.
  구간(인트로/자유 배회/심문)별 평균을 갈라 긴장 곡선이 실제로 존재하는지 본다.
- `probe-guidance.mjs` — 화면의 **가시 텍스트를 전수 수집**한다. "조작 안내가 있다"를 코드가
  아니라 화면에서 판정한다.
- `probe-tell.mjs` — 심문 카메라 컷별 프레임을 뽑아 **얼굴·양손이 프레임에 있는지** 본다.
- `probe-frames.mjs` — 제출용 후보 프레임을 고정 구도로 재촬영한다.

### 3.2 실측이 판정을 뒤집은 4건

**① 설계된 음악이 한 번도 울리지 않았다.** `music.js`에 인트로 서브 드론(41.2Hz, 25.7초)이
설계돼 있고 코드도 있었다. 프로브가 잰 결과는 **`musicOn` 샘플 0/339** — 전 구간 미발화였다.
원인은 레이스였다. `cinematic:start`가 첫 제스처(벨)와 같은 프레임에 오는데 AudioContext는 그
제스처에서 비로소 만들어지고, 벨 소리는 지연 큐(`playOrDefer`)를 타서 살아남는 반면 음악 큐에는
그 경로가 없어 조용히 버려졌다. **코드를 읽으면 "음악이 있다"이고, 실행을 재면 "음악이 없다"였다.**

**② 심문이 게임에서 가장 조용한 구간이었다.** 공포 추리에서 긴장이 올라야 할 자리다. 실측:
심문 −42.7dB vs 자유 배회 −34.5dB — **8.2dB 역전**. 환경음 감쇠(0.42)는 걸려 있는데 그 자리를
채울 층이 없었기 때문이다. 심문 긴장층을 넣은 뒤 재측정: 심문 **−23.2dB** vs 배회 **−32.6dB** —
**+9.4dB**로 뒤집혔다(`docs/reviews/fable-experience-2026-08-09-r3.md` §J6).

**③ "고쳤다"고 보고된 수정이 애초에 구현되지 않았다.** 노출 상한(창을 닫고 화면으로 돌아올 때
새하얗게 뜨는 현상과 천장을 올려다볼 때의 과노출을 막는 장치)이 완료로 보고됐다. 재판정
실측은 화면 복귀 노출 26.78→27.12(화이트아웃 없음), 올려다본 각 18.19 — **화이트아웃 현상
자체가 존재하지 않았고, 상한 코드도 없었다.** 고쳤다고 믿은 것이 아니라 **문제가 있다고 믿은
것**이 틀렸다. 재판정은 이걸 "반증 확인"으로 기록했다.

**④ 게이트가 오탐을 냈다 — 게임이 아니라 게이트가 틀렸다.** `probe-guidance`가 조작 카드를
FAIL로 판정했다. 프레임을 직접 보니 카드는 뜨고 4키가 전부 판독됐다. 원인은 프로브가 `engine.time
≥ 33`을 기다린 뒤 **벽시계 +1초**에 상태를 읽는데, 인트로 종료 시각이 실행마다 t=30.3~34.84로
흔들린다는 것이었다. 카드 수명(3.46 엔진초)이 판정점보다 앞서 닫히면 FAIL이 된다. 처방은
고정 시각이 아니라 `cinematic:end` 사건 결박이다. **게이트를 신뢰하되 게이트도 검증한다.**

### 3.3 하네스 함정 3건 — 측정을 오염시키는 것들

전부 실측으로 발견됐고 `tools/judge-probes/common.mjs` 머리주석에 계약으로 박혀 있다.

| 함정 | 무엇이 일어나는가 | 대응 |
|---|---|---|
| **엔진 시계 0.4배** | 헤드리스에서 `engine.time`이 실시간의 약 0.4배로 흐른다. 오디오는 실시간 시계로 스케줄되는데 시네마틱은 엔진 시계로 흐르므로, "16초 동안 유지"라고 적은 드론이 인트로 앞부분만 덮고 나머지가 무음이 됐다 | 시간 상수를 쓰지 않는다. 소리가 빠지는 시점을 **사건(`cinematic:end`)에 결박**해 기계 속도와 무관하게 만들었다(`src/audio/music.js:21`) |
| **낡은 판 PASS** | 샷 모드 vite는 파일 워처가 꺼진 채 뜬다. 소스를 고쳐도 **옛 변환 결과를 계속 서빙**하므로, 그 상태의 PASS는 수정 전 코드의 PASS다 | 소스 수정 후 vite 재시작 강제. 의심되면 서빙되는 판을 먼저 확인 — `curl -s …/src/<파일> \| grep -c <새 심볼>` |
| **교차 오염** | 병렬 세션이 같은 워킹트리를 서빙하므로 **남의 미커밋 WIP가 내 프레임에 섞인다**(실제로 한 세션의 조작 카드가 다른 세션의 블라인드 채점 프레임에 등장했다) | 자기 축 판정에만 쓰고, 남의 축이 찍힌 지적은 게이트로 넘긴다. **제출·판정용 최종 재촬영은 전 세션 커밋 후 게이트가 단독으로** 한다 |

세 번째 함정에는 짝이 되는 사고가 하나 더 있다. 판정 세션이 **배포본이 소스보다 3커밋 뒤인 것을
모른 채** 채점해, 이미 고쳐진 타이틀 화면을 "검은 화면(평균 휘도 13.3/255)"으로 기록했다. 그
뒤로 판정 문서는 첫 줄에 **배포 동일성 확인**을 적는다 — 원격 `gh-pages` 해시와 서빙되는 번들
blob이 같은 트리인지 대조한다.

### 3.4 이 하네스가 아직 판정하지 못하는 것 (정직 기록)

- **소리의 톤.** 기계는 RMS만 본다. "무섭게 들리는가", "1947년 라디오처럼 들리는가"는 판정 밖이다.
  그래서 사람이 헤드폰으로 도는 19항목 시트를 별도로 뒀다(`docs/submission/audio-listen-check.md`).
- **상용 게임으로 오인되는가.** 블라인드 비교는 사람 판정이고, 현재 결론은 "프레임을 통제하면
  유리하고 통제하지 않으면 중립"이다. 통제 없이 이겼다고 쓰지 않는다.
- **P2 범위.** 2·3막 레벨과 인물 4인의 텔 표본은 만들지 않았다. 게이트가 통과한 것이 아니라
  범위 밖이다(§7).

### 4.1 goal 계약 — 중단 조건 없는 발사 금지

**모든 goal은 세 필드가 필수다** — 목표 / 통과 조건 / **중단 조건**. 중단 조건(라운드 상한·토큰
상한)이 없는 goal은 발사 금지다. 패킷은 이 상한을 페이즈 예산에서 티켓 수로 나눠 자동 산출한다.
아래는 `packets/PACKET-T-P1-04.md` §1의 실물이다(생성물 원문, 편집 없음):

```
/goal 심문 1건 E2E — 소각 직렬화 포함 — T-P1-04
통과 조건: §8 수용 기준 4건 중 실행 가능한 전건 통과 · 콘솔 에러·경고 0 · §9 금지 사항 위반 0
           (§8 이 "도구 부재 시 건너뛴다"고 명시한 항목은 실행 불가로 보고 통과 계수에서 뺀다)
중단 조건: 라운드 상한 1회 · 서브에이전트 토큰 상한 150만
           (PROMPT-build-p1.md 의 P1 전체 상한 14회·1500만을 티켓 10장으로 나눈 몫)
           상한 도달 시 라운드 경계에서 끊고 §10 형식으로 인수인계한다. 중단 조건 없는 루프 금지.
```

*(인용 안의 "티켓 10장"은 이 패킷을 찍어낸 시점의 P1 티켓 수다. P1은 이후 12장으로 늘었고
패킷은 재생성되지 않았다 — 자동 생성물이 원천의 갱신을 항상 따라가지는 않는다는 실례이기도 하다.
여기 적힌 "1500만"은 **P1 단계에 미리 건 상한**이고, §5에 나오는 같은 자릿수의 1,500만은
**그래픽 라운드에서 실제로 쓴 양**이다. 우연히 자릿수가 겹칠 뿐 서로 다른 수치다.)*

같은 패킷 §2의 소유 선언과 §10의 반환 형식이 짝을 이룬다:

```
## 2. 소유 파일 (배타)
이 목록 밖의 파일은 읽기만 한다. 남의 파일을 고쳐야 하면 §10.1 형식으로 반환한다 —
"그 담당이 지금 안 보인다"는 안전 신호가 아니다.
 - src/narrative/interrogation.js — 파일 전체
 - tools/test-interrogation.mjs — 파일 전체
```

이 두 블록이 §2.1의 계약(배타 소유)과 §2.4의 규약(pathspec 커밋)을 **에이전트 1명의 시야
안으로** 옮긴다. 계약을 문서에 두고 "읽어라"라고 하는 대신, 발사문에 인라인해서 읽지 않을 수
없게 만드는 것이 이 시스템의 요점이다.

### 4.2 판정 발사문 — 채점자에게 거는 제약

판정 세션에는 반대 방향의 제약을 건다. `PROMPT-review-fable-3.md`가 건 것은 넷이다.

- **재발견 금지** — 이미 수용된 미달 7건은 인용만 하고 다시 파지 않는다.
- **기계 게이트 재실행 금지** — 채점자는 게이트를 돌리는 사람이 아니라 화면을 보는 사람이다.
- **함정 3건 회피 의무** — §3.3을 읽고 자기 측정이 오염되지 않았음을 문서 첫 줄에 적는다.
- **발주 금지** — 판정 세션은 코드를 고치지 않는다. 발견은 기록만 하고 다음 라운드로 넘긴다.

그 결과가 판정 3회의 문서다(`docs/reviews/`). 3차 판정은 발주된 13건 중 **10건 성립·2건 부분·
1건 반증**을 매겼다 — 즉 **발주자의 완료 보고를 그대로 받지 않았다.**

### 6.1 에셋 — 다운로드 3건 · AI 생성 1건 · 나머지 전부 절차 생성

텍스처·지오메트리·환경광·폰트·효과음·룸톤·리버브를 **하나도 내려받지 않았다.** **게임 월드
안에 보이고 들리는 것은 전부 런타임 절차 생성이다** — GPU 셰이더가 그리는 텍스처, 코드가
만드는 지오메트리, HDR 파일 없이 코드로 굽는 환경광, 시스템 폰트, WebAudio로 합성하는
효과음·잔향. 예외는 아래 둘뿐이고(파일 수로는 4개) 둘 다 사용자 승인분이다.

| 항목 | 파일 수 | 조달 | 출처·라이선스 |
|---|---|---|---|
| 타이틀 배경 `assets/title-bg.jpg` | 1장 | **AI 생성** | Codex CLI 내장 `image_gen` · 모델 `gpt-image-2` · 2026-08-09 생성 · 후처리는 `sips` JPEG 변환뿐. **프롬프트 전문은 credits §1.1**. 타이틀 화면 전용이라 **게임 월드 안에는 쓰이지 않고**, 파일이 없으면 인게임 로비 실렌더로 폴백한다 |
| 로비 라디오 BGM | 3곡 | **외부 다운로드** | Kevin MacLeod(incompetech.com) · **CC BY 4.0** · 표준 표기 전문과 후처리 명령은 credits §1.2 |

BGM 3곡은 비디제틱 배경음악이 아니라 **로비 소품인 라디오에서 나오는 디제틱 음원**이다 —
거리 감쇠·룸 리버브·심문 감쇠를 그대로 통과하고, 다이얼(E) 상호작용으로 국이 바뀐다. CC BY
4.0은 게임의 경우 **설정 메뉴 크레딧 노출**을 요구하므로(incompetech FAQ 원문) 설정 카드 하단에
저작자 표기를 넣었다. 파일이 없으면 편성표가 비고 절차 생성 방송만 남는다 — 외부 음원 없이도
게임은 성립한다.

**검증 명령**(빌드 경로의 바이너리는 이 4개가 전부다):

```bash
git ls-files src assets index.html | grep -iE '\.(png|jpg|hdr|mp3|wav|glb|woff2?|ttf)$'   # → 4행
```

## 7. 이 공정이 실패한 곳 (정직 기록)

조용히 빼지 않는다. 아래는 목표에 못 미친 채 제출되는 항목이다.

- **범위**: 2·3막 레벨(9층 복도·942호·옥상)은 만들지 못했다. 제출본은 **1막 수직 슬라이스**다.
  "넓게 잡으면 얇게 나온다"는 판단으로 1막 하나를 두껍게 가는 쪽을 택했고, 그 대가가 이것이다.
- **인상**: 자체 루브릭의 피크 조건(J1·J2·J3 중 하나 9점)이 불성립이다. 최고가 7이고, 세 축이
  걸린 자리는 전부 조명·구도지 기능이 아니다. 바닥 조건(4 이하 0개)은 성립했다. 판정 문서의
  표현을 그대로 옮기면 — *"'흠 없는 데모'에서 '바닥이 없는 게임'까지는 왔고, 피크 한 장이 없다"*
  (`docs/reviews/fable-experience-2026-08-09-r3.md` §2).
- **계약 린트 잔여 4건** — §2.1. 훅 도입 이전 위반이고 화면 표출과 무관하다.
- **하네스 오탐 1건** — §3.2④. 게임이 아니라 게이트의 결함이며, 처방까지 특정된 상태로 넘긴다.
- **사람 귀 미판정** — §3.4. 오디오 톤 19항목은 기계가 대신할 수 없다.

이 다섯 줄의 출처는 전부 **판정 세션의 문서**다 — 발주자가 스스로 적은 것이 아니라, 구현
컨텍스트 없이 배포본만 보고 채점한 쪽이 남긴 기록에서 그대로 옮겼다(§2.5·§4.2). 판정을
구현에서 떼어 놓으면 이런 목록이 나오고, 붙여 두면 나오지 않는다.
