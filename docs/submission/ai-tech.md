# 제출물 4 — AI 활용 기술 문서 (PDF 골격)

> 요강 필수 항목: **AI 활용 기술 설명(구조 설명, 주요 프롬프트·지시사항) / 외부 에셋·오픈소스 출처.**
> 출처 절의 진실원은 [`docs/credits.md`](../credits.md) — 이 문서는 그것을 인용하고 중복 기재하지 않는다.
> 대회 슬로건이 "AI를 활용하는 사람이 아니라 **AI의 다음 단계를 설계할 디렉터**"이므로,
> 이 문서의 승부처는 "무슨 도구를 썼는가"가 아니라 **"에이전트를 무엇으로 통제했는가"**다.

---

## 1. 한 줄 주장

이 게임은 AI로 만든 것이 아니라 **AI를 통제하는 시스템으로** 만들었다.
사람이 쓴 것은 목표·루브릭·게이트이고, 코드·문서·검증기는 에이전트가 썼다.
지시서조차 손으로 쓰지 않는다 — 데이터에서 찍어낸다.

## 2. 구조 — 4층

```
[0] 계약층    ARCHITECTURE.md — 파일 소유권·이벤트 어휘·재질/조명 팩토리·결정론
                   ↓ 위반은 커밋 훅이 차단
[1] 사양층    E0~E10 요소 문서 + case-graph.json — 한 사실은 한 파일에만 산다
                   ↓ 기계 전사
[2] 위임층    data/manifest/*.json (티켓 15장) → tools/packet-gen.mjs → packets/PACKET-*.md
                   ↓ 자기완결 발사문 1장 = 에이전트 1명의 소지품 전부
[3] 판정층    기계 게이트 — factcheck · pix diff · 완주 봇 · 계약 린트 · 샷 하네스
                   ↓ 통과한 것만 판이 갱신된다
```

**핵심은 [2]다.** 프로즈로 쓴 티켓 표는 읽는 에이전트마다 다르게 해석되지만,
매니페스트는 해석되지 않는다. 그래서 "어떤 에이전트가 봐도 같은 구조가 나온다".

### 2.1 계약층 — 에이전트가 서로를 망가뜨리지 못하게

병렬 에이전트가 같은 픽셀을 만져 무엇이 무엇을 망쳤는지 귀속 불가능해진 사고를 겪고
(`docs/RESUME.md` §5), 파일 단위 배타 소유로 전환했다. 남의 파일을 고쳐야 하면 고치지 않고
`docs/HANDOFF.md` 큐에 요청을 남긴다. 계약 위반 5종(materials 밖 재질 생성 · atmosphere 밖
광원 생성 · `Math.random()`/`Date.now()` 직호출 · 500줄 초과 · 표출 문자열 규약)은
커밋 훅이 기계로 차단한다.

### 2.2 사양층 — 형용사를 데이터로 내림

사건은 문서가 아니라 그래프다: `docs/design/case-graph.json` — 사실 25 · 증거 14 · 진술 14 ·
지목 링크 3 · 괴담 4. 거짓 진술에는 `refutedBy`(반박 증거)가 **필수**이고, 괴담 노드는
사건 인과에 참여할 수 없다. 이 규칙들을 `tools/factcheck.mjs` 가 F1~F4·R1~R3 로 감시한다 —
"진행 불능이 발생하지 않는다"가 신념이 아니라 통과/실패다.

### 2.3 위임층 — 지시서를 찍어낸다 (이 프로젝트 고유)

| 산출물 | 파일 | 역할 |
|---|---|---|
| 스키마 | `docs/design/manifest.schema.json` | 티켓 1장의 13 필수 필드 정의 |
| 매니페스트 | `data/manifest/T-P{0,1}-*.json` 15장 | 티켓 보드의 기계 전사본 |
| 검증기 | `tools/manifest-check.mjs` | 8규칙 — 소유 배타성·§ 좌표 실재·이벤트 어휘·순환 0·명령 실행 가능성 |
| 생성기 | `tools/packet-gen.mjs` | 티켓 → 자기완결 발사문 |
| 패킷 | `packets/PACKET-*.md` 15장 · 8,306줄 | 에이전트 1명이 받는 소지품 전부 |

**자기완결의 정의**: 패킷은 자기가 참조하는 계약 절의 **원문을 인라인**하고, case-graph
노드를 JSON 그대로 박고, 이벤트 표의 해당 행과 카메라 정의를 뽑아 넣는다. 받은 에이전트는
패킷 밖 문서를 열지 않는다. 질문이 나오면 **에이전트가 아니라 패킷을 고친다.**

**검증기가 실제로 잡은 것**(작문이 아닌 실측):
- 변이 12종 주입 시 12/12 검출 (허용값 밖 모델 배정 · 순환 의존 · 없는 절 지목 · 어휘 밖
  이벤트 이름 · 존재하지 않는 도구를 부르는 수용 기준 …).
- 정본 대상 실행에서 **티켓 보드의 실결함 1건 검출** — 두 티켓이 같은 파일을 소유하면서
  "상호 독립"으로 선언돼 있었다. 동시 발주하면 한쪽 산출물이 조용히 사라지는 구조다.
  `docs/HANDOFF.md` 등재.
- 배포 검증기(`tools/serve-check.mjs`)가 서브패스 배포에서 에셋 404 5건을 잡았다 —
  dev 서버로는 영원히 안 보이는 결함이다.

### 2.4 판정층 — 구현자와 판정자를 분리

| 축 | 판정 수단 | 상태 |
|---|---|---|
| 사실 그래프 | `tools/factcheck.mjs` | 가동 |
| 픽셀 회귀 | `tools/pix.mjs diff` + 기준선 스크린샷 | 가동 |
| 콘솔 에러·경고 0 | 샷 하네스 | 가동 |
| 계약 린트 | 커밋 훅 grep 5종 | 티켓 T-P0-01 |
| 완주 봇·시퀀스 캡처 | `tools/playthrough.mjs` | 티켓 T-P1-06 |
| 매니페스트 정합 | `tools/manifest-check.mjs` | 가동 |
| 배포 성립 | `tools/serve-check.mjs` | 가동 |

라운드 규율: **단일 담당 · 단일 목표 · 사전 기준선 → 사후 기계 게이트 · 라운드 단위 커밋.**
회귀면 롤백한다. 이 규율 자체가 "매 라운드 무언가 좋아지고 무언가 나빠지던" 진동
(3라운드 연속 평균 4.6)에 대한 대응이다.

## 3. 주요 프롬프트·지시사항 (요강 명시 항목)

원문이 전부 저장소에 있다 — 재구성이 아니라 실제로 발사된 것이다.

| 파일 | 무엇을 발사했는가 | 특징 |
|---|---|---|
| `PROMPT-plan-v1.md` | 기획 라운드 E0~E10 | 요소 분해 → 무질문 테스트 → 블라인드 채점 루프 |
| `PROMPT-build-p0.md` | P0 정지작업 5티켓 | 게임 코드 신규 기능 0, 청소·게이트만 |
| `PROMPT-build-p1.md` | P1 수직 슬라이스 7티켓 | "범위를 넓게 잡으면 얇게 나온다" — 1막 하나를 두껍게 |
| `PROMPT-system-v1.md` | 위임 시스템·제출 인프라 | 이 문서가 설명하는 §2.3 을 발주한 발사문 |
| `packets/PACKET-*.md` | 티켓 15장 | **자동 생성** — 손으로 쓰지 않는다 |

**모든 goal 은 세 필드가 필수다** — 목표 / 통과 조건 / **중단 조건**. 중단 조건(라운드 상한·
토큰 상한)이 없는 goal 은 발사 금지다. 패킷은 이 상한을 페이즈 예산에서 티켓 수로 나눠
자동 산출한다.

*PDF 에는 패킷 1장의 실물 발췌(§1 goal 계약 + §2 소유 파일 + §8 수용 기준)를 한 페이지 싣는다 —
"자기완결"이 형용사가 아니라는 것을 보여주는 가장 짧은 방법이다.*
